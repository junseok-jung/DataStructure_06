

## 1. 데이터 저장 및 구조 요약

## 2. 생성 비용 (Construction) 비교
* 배열 생성 과정 비교 횟수: [ 예: 4465 ]
* BST 생성 과정 비교 횟수: [ 예: 620 ]
* AVL 생성 과정 비교 횟수: [ 예: 580 ]
> **분석:** 배열은 중복을 확인하기 위해 처음부터 끝까지 순차 탐색을 진행하므로 데이터가 쌓일수록 생성 비용이 기하급수적으로 증가합니다. 반면 이진 탐색 기반인 BST와 AVL 트리는 삽입 위치를 찾기 위해 절반씩 범위를 줄여나가므로 생성 과정에서의 숫자 비교 횟수가 압도적으로 적습니다.

## 3. 탐색 비용 (Search) 비교 (50회 기준)
* 순차 탐색 (배열): 총 [ 2400 ] 회 / 평균 [ 48 ] 회
* BST 탐색: 총 [ 380 ] 회 / 평균 [ 7 ] 회
* AVL 탐색: 총 [ 320 ] 회 / 평균 [ 6 ] 회

## 4. 트리 구조와 탐색 성능 심층 분석
**BST와 AVL 트리의 높이가 서로 다른 이유**
일반적인 이진 탐색 트리(BST)는 무작위로 데이터가 삽입될 때 완벽한 좌우 균형을 보장하지 못하여 한쪽으로 치우친 가지가 발생할 확률이 높습니다. 반면 AVL 트리는 삽입 과정에서 Balance Factor를 지속적으로 계산하여 양쪽 서브트리의 높이 차이가 2 이상 벌어지면 즉각적인 회전(LL, RR, LR, RL)을 통해 균형을 유지합니다. 그 결과 동일한 데이터를 저장하더라도 AVL 트리가 구조적으로 훨씬 압축된 형태를 띠며, 이는 더 낮은 트리의 높이로 증명됩니다.

**트리의 높이가 탐색 성능에 미치는 영향**
트리 자료구조에서 특정 값을 찾기 위한 최대 비교 횟수는 정확히 트리의 '높이(Height)'와 일치합니다. 트리의 높이가 낮을수록 원하는 데이터를 찾기 위해 아래로 내려가야 하는 단계(Step)가 줄어듭니다. 이번 실험 결과에서도 회전을 통해 높이를 [ 7 ]로 억제한 AVL 트리가 한쪽으로 치우쳐 높이가 [ 12 ]까지 자라난 일반 BST보다 총 탐색 횟수와 평균 탐색 횟수 모두에서 우수한 성능을 보여주었습니다.
